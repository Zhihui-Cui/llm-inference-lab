## 2. 数值证据及测试意义

环境：WSL、Python 3.12.3、PyTorch 2.14.1+cpu、CPU float32。SDPA 使用完全相同的 Q/K/V、布尔下三角 mask，`dropout_p=0.0`；容差 `rtol=1e-5, atol=1e-6`。种子和源码 SHA256 记录在原始结果中；不同 Q/K/V 的 batch 补验使用种子 123。没有 GPU、性能或生成质量结论。

| 对照 | 最大绝对误差 |
|---|---:|
| T=3 手写 / SDPA | 3.814697265625e-06 |
| T=2 手写 / SDPA | 1.9073486328125e-06 |
| T=1 手写 / SDPA | 0 |
| 原练习 batch / SDPA | 3.814697265625e-06 |
| 不同 Q/K/V 的 batch / SDPA | 2.384185791015625e-07 |
| 短输入重算 / 长输入前缀 | 0 |
| 只修改 batch 第 2 份后，第 1 份输出变化 | 0 |

通过容差不是要求最大误差小于单独的 atol，而是逐元素满足 `abs(actual-reference) <= atol + rtol*abs(reference)`。

检查不仅比较两个结果“差不多”，还保留明确应失败的对照：

- 零 Q、位置 2 的头 2：因果输出应为 [0,30]；去掉 mask 得 [0,40]。40 在不加掩码的计算中正确，但不满足当前因果任务；不能拿它当因果参考值。
- 拆头后直接 reshape 回 [T,D] 会混淆元素归属，标记检查能识别。
- M10 改“我爱学”的最后一字为“我”，位置 2 输出仍是 [0.5679882765,0.2816824913]，这是正确的因果行为；它不能独自识别误用旧 V 的错误。
- 同一组参数下倒序为“学爱我”，位置 2 输出变为 [0.6291848421,0.4622327089]；第一位置必须等于新 V 的第一行。故意换回旧 V 后，该断言失败。此前使用旧 V 算出的倒序差异不作为正确性证据。

M07 原练习单步 MSE 为 0.9152989388 → 0.7279464006；本次另建 batch 检查为 0.5730739236 → 0.4454117119，二者是不同实验。下降只说明这些固定输入下的一次更新有效，不能证明语言学习或泛化。
